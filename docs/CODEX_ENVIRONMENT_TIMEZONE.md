# Codex 正文环境时区

## 使用

在「代理管理」重新测试已有代理（单条或批量均可），检测会在原 IP 查询中获取 IANA 时区，无需在模型请求过程中额外访问地理服务。

- IP 下方显示实际生效的时区，例如 `America/Los_Angeles`。
- 「编辑代理 → Codex 正文时区（手动覆盖）」留空默认用推测值；填写有效 IANA 时区可覆盖，清空恢复自动。
- 自动检测值 `test_timezone` 与手动值 `timezone_override` 分开持久化，重启后保留。再次测试只更新自动值，不覆盖手动设置。
- 测试失败保留上次推测值；同一 IP 暂缺时区也保留。成功检测到不同 IP、却没有有效时区时清空旧推测，防止继续使用旧出口信息。
- 修改代理 URL 清空旧检测值，保留用户明确设置的手动覆盖。旧 URL 的迟到测试结果不能覆盖新 URL。
- 未测试过时区的旧代理、未登记的代理、直连均不猜测时区，保留原正文。Resin 的出口由 Resin 决定，不能用未实际使用的代理配置推测，因此暂不改写 Resin 请求。

## 改写范围

仅 Codex 原生 Responses HTTP、WebSocket 和 HTTP compact 上游链路；不修改 NewAPI、其他渠道和 Responses 中转账号链路。

正文时区独立于设备/会话指纹模式，在 off、仅设备、会话和完整收敛下均按实际代理的时区设置处理。

只识别 `input` 消息中独立的 `<environment_context>...</environment_context>` 文本，改写最新环境块内的两个直接子元素：

- `<timezone>`：改为实际出口对应的手动或自动 IANA 时区。
- `<current_date>`：使用同一个当轮参考时刻，转换为目标时区下的日期，自动处理跨日和夏令时。

优先从当前帧的 `turn_started_at_unix_ms` 获取参考时刻，否则使用网关接收时间。同一请求的重试固定参考时刻，并按出口缓存时区快照；换出口时使用对应出口的配置。WS 续链复用以连接实际建立时的代理为准，而非本次请求新选的代理。

不修改 cwd、Shell、工作区、文件系统权限、工具/技能路径、普通用户文本、工具输出、设备和线程字段，也不改 `web_search.user_location`。时间戳仍代表同一个瞬间，不做偏移加减。

历史环境块不批量重写。最新块的日期必须与参考时刻在原时区的日期一致，才联动改写日期与时区；历史日期、无效时区或不完整 XML 保留原文。仅含时区的增量环境块可以更新时区，不凭空补字段。

没有环境块的增量帧不注入新消息，也不把上一帧正文复制过来；服务端已有历史、加密压缩内容不回写。修改设置后，如后续帧没有新的环境块，应新建会话或等客户端发送环境更新，不能保证立即覆盖远端既有上下文。

## 效果示例

同一个参考时刻 `2026-09-06T00:30:00Z`，上海为 9 月 6 日早上，洛杉矶为 9 月 5 日下午：

```xml
<environment_context>
  <cwd>F:\codex</cwd>
  <shell>powershell</shell>
  <current_date>2026-09-05</current_date>
  <timezone>America/Los_Angeles</timezone>
</environment_context>
```

原来的日期为 `2026-09-06`、时区为 `Asia/Shanghai`；其余字段不变。IP 地理推测不是远程主机系统时区，也不能保证不同地理库或轮换出口始终一致。
