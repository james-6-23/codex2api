# 用户窗口扩容与账号保留位

## 配置与上线

1. 先升级 Codex2API，再升级 NewAPI；默认不会自动开启收费。
2. Codex2API 的账号「活跃会话容量」填写总容量及保留位。例如总容量 10、保留 2，普通池为 8。默认保留 0，支持单个编辑与批量编辑。
3. NewAPI「个人 → 窗口管理」底部管理员策略选择已有签名联动的 Codex2API 渠道 ID，配置额外窗口和倍率，再开放扩容。默认策略关闭，额外 5 个、倍率 1.5；可设置额外 1–100 个、倍率 >1 且 ≤10，最多 16 个渠道。
4. 用户在同一页面确认当前价格后开启。仅真实、签名验证通过的 NewAPI 用户参与扩容。UA、指纹、用户自己设置的 HTTP 头均不能获得保留位。

账号列表保持紧凑：`会话 1/8 · 保留 0/2`。总容量包含保留位，不是在总容量之外再增加；没有配置保留位时保留原来的展示。

人物画像 → NewAPI 用户详情 → 当前活跃窗口显示 `普通窗口 · ×1` 或 `扩容窗口 · ×1.5`，读取窗口创建时保存的真实档位，不根据用户当前开关或账号保留位推断。这里只展示尚未到期的窗口，不是历史扩容报表；历史实际收费可查看 NewAPI 用量日志详情中的窗口档位及倍率。展示复用现有窗口状态读取，不增加跨平台查询或日志扫描。

## 定价与分配

- 用户先用普通窗口额度，普通额度满后才创建收费扩容窗口。是否扩容取决于根窗口，而不是模型名称或用户开关本身。
- 倍率固定在窗口周期内，叠乘原费用；正常、按次、动态计费的预扣和结算都使用同一倍率，动态表达式失败回退时不会重复乘。用量日志详情显示本次普通/扩容档位及倍率。
- 关闭用户开关或全站开关仅停止新的扩容授权，已有窗口不重定价。超过用户已确认倍率的涨价需要重新确认；降低倍率可用于之后新建的窗口。不要在旧窗口到期前移除相关服务池或签名绑定。
- 子请求/审查/压缩复用可识别的根窗口档位；无根的后台请求不能独立创建收费窗口。已有模型限制、会话锁、创建 CD 和并发限制仍然生效。
- 已验证扩容请求可占账号保留位；在所选账号内优先使用保留位，再使用空闲普通位。不强行迁移已有根账号，不保证在不同账号之间优先挑有保留位的账号。
- 普通请求不能使用保留位。一个账号窗口继续活跃但付费用户窗口已经到期时，新的普通档位必须有普通位才能接续，不能免费继续占用保留位。降低容量不驱逐已存在的窗口；空闲回收沿用账号原有周期。

## 协议与一致性

`POST /v1/session-windows` 使用原有 API Key 鉴权及 NewAPI 身份/元数据签名，提供 `list`、`quote`、`release`。

NewAPI 在预扣前申请档位；Codex2API 以平台+用户为键，事务更新 `prompt_user_window_grants`，同一根返回同一档位。暂存授权最多保留 30 秒，实际窗口准入时确认；失败预扣或失败请求释放未使用的授权，创建 CD 回滚也清理对应授权。创建 CD 的使用样本仍遵循原有成功请求口径。

授权使用独立 HMAC 域签名，绑定平台、用户、Codex2API API Key、根指纹、窗口 ID、到期时间和倍率。NewAPI 校验后将授权放入签名元数据；Codex2API 验证后才允许保留位。控制调用每次使用独立请求 ID，避免与真实模型调用触发防重放冲突。票据不向个人页面、用量日志或上游模型泄露。

预扣后锁定该次调用的签名目标与档位，关闭自动跨渠道重试；路由变化报错并退回预扣，不能换目标后带着旧档位继续扣费。容量拒绝仍为不重试的 400，并保留最近恢复时间提示；服务故障为 503，不能伪装为使用量为零。

## 性能与边界

- 个人列表只查询配置的服务池及当前已登录用户。相同平台/规范化目标去重，最多 4 路网络并发，网络总预算 2.5 秒，每目标最多 2 秒；复用渠道的代理与连接池。
- 列表缓存 15 秒，并合并同一用户的并发查询；页面仅可见时定期刷新，倒计时在浏览器完成，每池初始渲染最多 50 个窗口。
- 模型调用成功后缓存授权至到期，常规续聊无额外跨服务查询。失败会清除对应缓存，避免反复复用失效授权。缓存数量有界。
- 账号保留计数复用原有窗口清理遍历，不另扫日志。个人 CD 展示读取索引定位的上次评估结果，不重新汇总画像或历史样本；最终是否可创建以实际请求时评估为准。
- 各独立 Codex2API 服务池分别限额，不提供跨独立数据库的全局额度。账号窗口并发保证沿用现有调度进程的互斥/运行时缓存机制；不新增同一账号跨多个独立调度进程的分布式容量锁。此类部署应继续使用单一调度所有者/粘性路由。
- 不设用户窗口限制、或普通额度大于 1000 的用户沿用原有普通窗口处理，不新建收费扩容窗口，避免扩容状态无限增长；已有收费窗口仍保持原价到期。这类只使用普通窗口的查询结果短缓存 5 秒。
- 已有 HTTP Responses/Chat/Claude 及后端 WS 调度继续使用原有入口；不会新增 NewAPI 原本不存在的 Responses WS 入站接口。没有可验证根身份的请求不参与扩容。
