# Codex 容量不足重试

设置 → 过载自动暂停 → **容量不足自动重试**（`codex_capacity_retry_enabled`）。新安装和旧数据库升级后均默认关闭，与过载熔断独立。

| 开关 | 网关行为 | 最终下发 |
| --- | --- | --- |
| 关闭 | 容量不足/过载立即结束，不补试 | 保留上游容量错误码和文案 |
| 开启 | 仅按对应通道现有的有限次数补试 | 耗尽后仍保留上游容量错误码和文案 |

- HTTP 请求使用“最大重试次数”，HTTP 429 使用独立的“429 重试次数”；原生 Responses WebSocket 使用已有的 WS 静默重试开关和次数。次数 1 表示首次请求之后最多补试一次，不保证账号/连接不可用时一定能补试。
- 容量错误不会因“持续重试”、超级模式或精确错误码选择器变成无限重试。其他错误的重试规则不变。
- 已经发给客户端的流式内容不重放；未提交的暂存内容可以在有限预算内丢弃重试。
- 不再将 `server_is_overloaded` / `slow_down` 改写为 `server_error`。错误码、类型及文案保留；JSON 错误文案仍经过敏感信息脱敏和长度限制，不暴露完整内部诊断。
- HTTP 尚未提交时返回 **400**，并移除 `Retry-After`，避免 NewAPI / 客户端常规 5xx、429 重试。这里保留的是原始错误语义，而不是原始 HTTP 状态；内部用量日志仍记录上游真实状态。
- SSE 已提交时使用对应协议的错误事件；WS 首包前终止使用原始结构化错误及 1008 关闭码，不使用 1013“稍后重试”。WS 的通用隐藏错误开关不覆盖这类容量提示。
- 识别结构化错误中的 `server_is_overloaded` / `slow_down`，以及明确的 `Selected model is at capacity` 文案；不把普通 500、余额不足或所有 429 当作模型容量不足。

该设置限制本服务的自动补试，并避免主动诱导下游重试；无法阻止用户手动重发，或客户端/NewAPI 自定义策略强制重试 400。
