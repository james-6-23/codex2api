# 7d 成本窗口重置

账号列表中的三类数据使用不同口径：

- 7d 百分比来自上游用量快照。
- 请求数、Token 数仍为最近七天滚动聚合，不随额度重置整体归零。
- 7d 成本以 `reset_7d_at - usage_window_7d_seconds` 为统计起点；周期秒数缺失时回退七天。

长窗口（包含 7d / 30d）的重置时间向后移动超过 5 分钟时，重新建立成本起点，从新周期范围统计。旧周期成本不再继续累加；新周期已经产生的消费仍会显示，因此重算不等于界面一定出现零。

保留 5 分钟容差用于抵抗秒级时间抖动，不再将长达 24 小时的移动视为同一长窗口。容差相对已保存的固定起点比较，不随每次微小抖动不断后移。旧进程返回的更早同周期快照不能将起点回退。周期长度修正但重置边界基本相同的场景继续保留原有归档成本处理。5h 的原有容差不变。

仅百分比下降、重置时间不变时，不凭百分比猜测新周期。

前端在当前页已有账号出现新的有效长窗口、显著向后变化的重置时间或有效周期修正时，补拉一次当前页统计；不添加定时轮询，不随每次百分比变化请求。手动重置成功后也补拉统计。重复快照、缺失元数据、微小抖动和旧快照不会反复触发查询。

本次不增加数据库表、索引或请求转发链路上的查询。正常同周期读取仍只读状态，仅边界变化时执行已有原子更新。

回归覆盖：周窗/月窗提前重置，5 分钟边界，已有日志/已归档日志，重复读取不重复写入，旧快照防回退，页面补拉触发与抑制。
