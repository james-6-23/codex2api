# 额度耗尽时的会话续聊切换补丁

## 原因与修正

原逻辑把携带 `X-Codex-Turn-State` 的活跃回合固定在原账号。即使账号已被上游确认耗尽额度，也可能直接返回 429；原测试明确要求这种行为。

补丁允许 HTTP 和 WebSocket 在上下文能够完整重放时解除这项绑定，使用现有调度器选择有额度、符合模型和 API Key 分组权限的账号。切换时清理旧的回合状态及旧 `previous_response_id`，保留已重建的历史、工具调用和工具结果。

另修正周限额冷却来源判定：`usage_limit`、`usage_limited`、`rate_limited_7d` 是上游明确的限额结果，不能因冷却时间恰好等于周窗口重置时间而被误判成本地用量快照。

只收到本地 WHAM 100% 快照、而上游尚未拒绝当前回合时，保留原有继续完成回合的逻辑。

## 行为边界

- 请求尚未产生客户端可见内容时，限额失败使用现有有限重试预算切换账号。HTTP 429 和流内 `response.failed` 均覆盖。
- 原账号在请求开始前就已确认无额度时，直接进入可用账号调度，不先发送一次必败请求。
- 带 `previous_response_id` 的 WebSocket 请求先按原有 owner 隔离、缓存和大小限制恢复完整历史。不会使用丢失历史的 fail-open 模式来完成本补丁的切换。
- 缓存缺失、工具结果缺少原调用、`item_reference` 或不可跨账号重放的加密压缩状态，明确返回上下文不可恢复错误。加密 reasoning 会先随请求转发；如果替代账号拒绝它，现有重试路径可能移除该隐藏推理后再试。
- 已经向客户端发送真实内容后不重放同一输出，避免重复文字、工具调用或副作用。因此不能承诺任意阶段的错误都绝对无感。
- 账号全部耗尽、没有权限使用其他账号，或重试预算已用完时仍会返回错误。
- 普通请求保持实时流式输出，不启用整段回答缓存或无限重试。
