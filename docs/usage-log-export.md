# 使用日志下载

使用统计的请求记录工具栏提供两个按钮，每次都需要确认；取消确认不会请求导出接口。生成期间可以取消下载，且暂时不能清空日志。

- **按筛选下载**：以点击时的时间范围、请求类别、搜索、渠道、账号、模型、状态、压缩、重试和 HTTP/WS 等筛选为准，导出所有匹配记录，不限当前页。
- **全部下载**：忽略所有筛选，导出数据库仍保留的全部使用日志，包含所有渠道、时间、状态、取消及内部请求。不会恢复已经删除的明细，也不包含独立的服务错误日志表。

文件为普通 `.json`，包含 `version`、`scope`、`generated_at`（UTC）、`filters`、`logs`、`total` 和 `complete`。每条记录保留日志 ID、请求/上游请求 ID、用户及账号信息、用量、错误、请求类别，以及 `diagnostics` 中已保存的会话关联、最终出站与连接诊断。缺失诊断为 `null` 或原有缺失标记，不反推、不补造；损坏的历史诊断显示 `capture_status=invalid_stored_json`。可用的 WS 生命周期缓存会像单条详情一样补充。

不导出账号凭据对象或原始 API Key；诊断中的认证头、Cookie、令牌、请求/响应正文等敏感字段会移除。设备和会话 ID、邮箱、IP、用户标识仍保留，错误文本也可能包含业务信息，分享前需要自行检查。下载只发生在本机，不自动上传。

管理接口为 `POST /api/admin/usage/logs/export?scope=filtered|all&confirmed=true`，使用已有管理员鉴权。`filtered` 复用使用日志的筛选参数，必须提供合法 `start/end`；忽略 `page/page_size`。未确认、无效范围或模式返回 400。同一服务实例同时只生成一份使用日志导出，忙时返回 409。

页面使用同一接口的 `paged=true` 模式，不再等待完整临时文件生成。每次最多读取 200 条，通常不超过 4 MiB 记录正文，单条超大记录保持完整；单批数据库查询超时为 30 秒。后续请求使用不透明 `cursor`，按创建时间及 ID 双字段翻页，不使用 OFFSET 或每页 COUNT。第一批固定最大日志 ID，后续新增记录不混入当前导出，游标同时核对筛选和生成时间。多实例只需共享原数据库，不依赖某个进程中的后台任务。导出过程中其他管理员清理的记录无法恢复，因此不要同时清理日志。

页面显示已读取条数、体积与已发起下载的分卷数量。网络中断、繁忙或临时网关错误最多重试当前批次两次，成功接收后才推进游标，不重新追加已完成批次。取消会中止当前请求，未完成分卷不会保存；此前已保存的分卷仍保留，并提示整个导出尚未完成。每条记录作为原始 JSON 文本传递，避免浏览器解析再序列化导致大整数精度丢失。

为限制浏览器内存，大数据自动拆为约 32 MiB 的独立 `.json` 分卷；请允许站点下载多个文件。每卷 `total` 表示本卷条数，`complete=true` 表示本卷文档完整；`part` 为卷号，`exported_records` 为累计条数，只有最后一卷 `export_complete=true` 才表示整个导出完成。分享批量日志时应提交所有分卷。超大单条记录可能使单卷超过目标大小。重试是本次下载过程内的批次重试，不提供关闭页面后的断点恢复。

未传 `paged=true` 的旧接口保持兼容：先写临时文件，完成后发送附件，准备超时为 10 分钟。直接调用旧接口仍可能遇到长时间无响应或浏览器大 Blob 限制，页面已不再使用此路径。
